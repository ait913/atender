予定 1 件の要素デザイン — 6 案

RoomCalendar (週/日/月) と RoomTimetable で適用する「1 件の予定」要素を 6 案比較。 現状: 純色背景でごちゃつく + padding 過多 という Touri フィードバックに対し、 各案で「左 color label + 落ち着いた背景 + 8pt 準拠 padding」をベースに、 塗り方・余白・タイポを変えて検証する。 全案で同じシナリオ (5-7 件混在 + 重なり) を render。

Architect への申し送り (参考)

  • 「眩しさ低減」と「学生馴染み」を両立できるのは 01 Tint+Bar または 06 Things Min。01 は Penmark/TimeTree 互換、06 は Things/Notion 互換。
  • 03 Linear Mono は情報量が最大化される (= 沢山並んでも疲れない) が、メンバー色が小さすぎるので「誰の予定か瞬時に判別」要件には弱い。
  • 04 Apple Glass は Android Chrome の古いバージョンで backdrop-filter performance 劣化、また iOS でも timegrid 内で重ねた時に再描画コスト発生。E2E テスト時要検証。
  • 05 Snap Pop は Snap token と一番親和するが、chip + 左 bar + grad で色情報が 3 重に増える。5+ 件並んだ時に「うるさい」と感じやすい。
  • 02 Notion Cal は最も「呼吸」する設計だが、学生 UI としては Penmark に近すぎず、馴染みのなさが導入障壁になる可能性。
  • 左 color label の太さ: 01=4px / 02=2px / 03=dot 8px / 04=1.5px glow / 05=4px + chip / 06=3px。4px が太すぎず細すぎず、TimeTree との比較でも標準値。
  • padding は全案 8pt grid 準拠 (主に 8px 12px) を採用。現状の Atender 実装は 12-16px 過多なので、どの案を採っても余白は減る。
  • 狭い lane (3 分割で 100px 以下) で chip 等を省略する fallback ルールは 06 Things Min のみが明示。他案にも適用すべき。
