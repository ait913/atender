## 1. スケルトンの実 UI 整合

- **実コンポーネントの外殻クラスをそのままコピーする** (角丸・padding・gap・bg を一致させ、ロード完了時のレイアウトシフトをゼロにする)

- プレースホルダ個数は **index ベースの決定的パターン** で配置 (乱数禁止 — テスト可能性のため)
- プリミティブは既存 `apps/web/src/components/ui/Skeleton.tsx` (`aria-hidden="true"` を自動付与) を使う。変更しない

## 2. 本日の記録 CTA: 下部固定 + 上方向展開に統一

### 現状の問題

- モバイル: 画面下部 fixed でパネルは**上**に開くのに、矢印は閉=ChevronDown / 開=ChevronUp で逆
- PC: `sticky top-14` でパネルが**下** (mt-3) に開く。要望は「PC もスマホ同様上側に展開」

### 新レイアウト (MainAttendanceCTA.tsx)

モバイル/PC のセクション 2 つを **1 つの fixed セクションに統合**する:

```
モバイル (<md):                          PC (md+, SideNav w-60 あり):
┌──────────────────────┐                ┌────┬─────────────────────┐
│      (コンテンツ)      │                │Side│   (コンテンツ)        │
│                      │                │Nav │                     │
│ ┌──────────────────┐ │                │    │ ┌─────────────────┐ │
│ │  ExpandedPanel   │ │ ← 展開時のみ    │    │ │  ExpandedPanel  │ │
│ ├──────────────────┤ │   (上に出る)    │    │ ├─────────────────┤ │
│ │[今日は全出席(3)|⇅]( ⌃ )│             │    │ │[全出席(3)|⇅] ( ⌃ )│ │
│ └──────────────────┘ │                │    │ └─────────────────┘ │
│ ▒▒▒ BottomTab ▒▒▒▒▒ │                └────┴─────────────────────┘
└──────────────────────┘                  ↑ bottom: 0 (BottomTab は md:hidden)
  ↑ bottom: var(--tab-bar-height)
```

```tsx
export function MainAttendanceCTA(props: Props) {
  const keyboardOpen = useIsKeyboardOpen();
  if (keyboardOpen) return null;
  return (
    <section
      className="fixed inset-x-0 bottom-[var(--tab-bar-height)] z-40 border-t border-fg-primary/8 bg-bg-base/85 py-2 backdrop-blur-xl md:bottom-0 md:left-60"
      role 等は付けない (現状どおり)
    >
      <div className="mx-auto w-full max-w-[920px] space-y-2 px-3 md:px-6">
        {props.expanded ? <ExpandedPanel {...props} /> : null}
        <CTAButtons {...props} />
      </div>
    </section>
  );
}
```

- `md:left-60`: SideNav (`w-60`) を避ける。`md:bottom-0`: BottomTab は `md:hidden` なので PC は画面最下端
- inner の `md:px-6` は AppLayout main の `md:px-6` に揃える
- ExpandedPanel は常にボタン行の**上** (DOM 順で先) = 上方向展開
- 旧 PC 用 `sticky top-14` セクション (L32-35) は削除

**矢印の向き** (CTAButtons L98): パネルは常に上に開くので

- 折りたたみ時 → `<ChevronUp />` (上に開く予告)
- 展開時 → `<ChevronDown />` (閉じる = 下に戻る)

aria-label (`個別修正を開く` / `個別修正を閉じる`) は現状維持。

**Home.tsx**: root の `pb-32 md:pb-0` を `pb-32 md:pb-24` に変更 (PC でも下部 CTA がコンテンツ末尾を覆わないように)。変更はこの 1 クラスのみ。

## 3. 一括記録の status 選択 (mark-all 拡張)

### UI/UX: split button + 上開きメニュー

CTAButtons の一括ボタンを split button 化する:

```
┌─────────────────────────────┬────┐   ┌────┐
│   今日は全出席 (3)            │ ⇅  │   │ ⌃ │ ← 既存の個別修正トグル (変更なし)
└─────────────────────────────┴────┘   └────┘
                              ↑ ChevronsUpDown アイコン
メニュー (トリガー押下で split button の真上に absolute 表示、上方向):
┌──────────────────┐
│ 全部 欠席 (3)     │  ABSENT
│ 全部 公欠 (3)     │  EXCUSED
│ 全部 遅刻 (3)     │  TARDY
│ 全部 早退 (3)     │  EARLY_LEAVE
└──────────────────┘
```

- **メイン部** (左): 既存 `Button` のまま、label 現状維持 (`今日は全出席 (N)` / 完了時 `本日の記録は完了済`)。className に `rounded-r-none` を追加して右端を直線に。click → `onMarkAll("PRESENT")`
- **メニュートリガー** (右): `<button>` で `Button` と同高 (`min-h-12`)、`w-11`、`rounded-r-full rounded-l-none`、メイン部と同 variant 色 (`unrecorded === 0` のとき secondary 色 / それ以外 primary 色) + `border-l border-fg-on-accent/25` (secondary 時は `border-fg-primary/15`)。アイコン `<ChevronsUpDown className="h-4 w-4" strokeWidth={2.5} />` (lucide-react 1.16.0 に存在確認済)。`aria-label="一括記録のステータスを選ぶ"` `aria-haspopup="menu"` `aria-expanded={menuOpen}`
- **メニュー**: split button を包む `relative` div 内に `absolute bottom-full left-0 right-0 mb-2 z-50` で表示。`rounded-2xl bg-bg-elevated p-1.5 shadow-card`、`role="menu"`。項目は `role="menuitem"` の `<button>`、label は `全部 {statusLongLabels[status]} ({N})` (statusLongLabels は `ui/labels.ts` 既存)。対象 status は `ABSENT / EXCUSED / TARDY / EARLY_LEAVE` の 4 つ固定順
- **CANCELLED はメニューに含めない**: 休講は CourseSuspension 系統 (分母制御) の領分で、一括「休」入力は出席率の意味論を壊す。個別修正パネル (ExpandedPanel) の 6 ボタンは現状のまま (個別なら休も選べる)
- menuOpen は MainAttendanceCTA 内の local state (`useState<boolean>`)。閉じる条件: 項目選択時 / トリガー再押下時 / 外側 pointerdown 時 (document リスナー、メニュー要素外判定) / Escape keydown 時
- disabled 条件はメイン部と同一 (`pending || unrecorded === 0` でトリガーも disabled、disabled 中は menuOpen を開かない)
- メニュー項目押下 → `onMarkAll(status)` を呼び、menuOpen を false に

### Props 契約 (MainAttendanceCTA — render テストはこれを根拠にする)

```tsx
type BulkAttendanceStatus = Exclude<AttendanceStatus, "CANCELLED">;
// = "PRESENT" | "ABSENT" | "EXCUSED" | "TARDY" | "EARLY_LEAVE"

type Props = {
  occurrences: OccurrenceDto[];                 // @atender/shared。status: AttendanceStatus | null を含む
  expanded: boolean;                            // 個別修正パネル開閉
  onToggle: () => void;
  onMarkAll: (status: BulkAttendanceStatus) => void;   // ← 変更: 引数追加
  onChangeStatus: (id: string, status: AttendanceStatus) => void;
  pending?: boolean;
};
```

## 不採用案

- **PC は sticky top のままパネルだけ DOM 順で上に出す**: sticky top 配置で「上に展開」すると TopBar (top-14 の根拠) と衝突し、視覚上は「ヘッダ直下からさらに上に生える」不自然な動きになる。下部 fixed への統一が要望 (スマホ同様) にも合致するため却下
- **mark-all-present のリネーム (`/api/attendance/mark-all`) と `MarkAllPresentInput` の改名**: デプロイ済み API + iOS foundation (20260608) + 既存テスト群との互換を壊す割に得るものが名前の正確さだけ。status optional 拡張で後方互換を保つ方を採用。名称と実態のズレは本 doc とコード上のコメント不要 (zod schema が自明)
- **一括メニューに CANCELLED (休講) を含める**: 休講は CourseSuspension (分母制御) の系統で、AttendanceRecord として一括投入すると出席率計算の意味論と衝突する。個別修正パネルでは引き続き選択可なので機能欠損はない
- **記録済 occurrence を一括 status で上書きする**: 「一括」は未記録の穴埋めが目的。上書き許可は誤タップ一発で当日の記録全部が壊れる導線になる。上書きは個別 API の領分として skip 維持
- **zod `.default("PRESENT")` で status 解決**: `z.infer` (output 型) では status が必須になり、クライアント側 `MarkAllPresentInput` 型の使い勝手が崩れる (z.input との使い分けが必要になる)。`?? "PRESENT"` をハンドラ 1 箇所に書く方が単純
- **ListSkeleton (Friends/Rooms) の作り直し**: 行高は実カードと一致しており違和感は軽微。今回のスコープ膨張を避けて見送り (将来 FriendCard 形状が変わったときに合わせて再考)
- **viewMode 別スケルトンを 1 コンポーネント (`CalendarSkeleton viewMode={...}`) に統合**: 既存 skeletons ディレクトリは「1 用途 1 ファイル」の粒度で揃っており、分岐入りの統合コンポーネントは既存規約から逸脱する。3 ファイル新規の方が既存パターンに整合
- **メニューを BottomSheet (既存 sheet コンポーネント) で出す**: 4 項目のためにフルシート遷移は過剰。CTA 直上の軽量メニューの方が「ワンタッチ出欠」の思想に合う
