# Atender 全面 redesign 設計 doc (2026-05-15)

## Executive Summary

MVP の機能脳死実装 (UX 配慮ゼロ・aisaba 流用の黒背景 + `Atender::` 装飾) を、**学生向け時間割アプリのデファクトである Penmark 系 UX** に全面差し替えする。背景白 + ミントグリーン accent (`#10B981`) + bottom tab 5 個 (`今日 / 時間割 / みんなの時間割 / 出席率 / マイページ`) + bottom sheet 主導の CRUD で再構築。schema (Prisma) は **完全に維持**、API は CRUD 補強 (個別 Meeting / Course CRUD + DaySlot 一括置換) のみ追加、Web は全画面再実装。

主要 UX 判断 5 つ:
1. **Design 言語 = Penmark ライク確定**: `#FFFFFF` 背景 + `#10B981` accent + `Inter` + `Noto Sans JP` + 角丸 12px (aisaba 流用は撤回)
2. **ナビ = bottom tab 5 個 (モバイル) / left sidebar (≥768px)**: `today`, `timetable`, `templates`, `stats`, `me` ルートに renaming (旧 `/settings` → `/me`)
3. **時間割エディタ = セル tap で bottom sheet**: 空きセル → 追加 sheet、既存セル → 詳細 sheet (編集/削除ボタン)、連続コマは `grid-row: span N` でセル merge
4. **CRUD 完備**: Meeting / Course / DaySlot / UserTimetable に **個別 PATCH / DELETE endpoint** を追加 (MVP は UserTimetable 一括 PATCH だけだった)。フロントは個別 mutation + TanStack Query invalidation で「リロードしないと反映されない」問題を根治
5. **Home (`/`) = 「今日」**: 上部に今日の時間割ミニビュー + 当日 occurrence カード縦並び + 出欠切替 bottom sheet + sticky CTA「全部出席」

## 2. Design 言語 (確定)

Researcher §7 推奨「案 B: Penmark ライク (Soft & Youthful)」を採用。aisaba 流用案は **不採用** (理由: §9 #1)。

### 2.1 カラートークン

すべて Tailwind 4 + CSS custom properties で定義。`apps/web/src/styles.css` の `:root` に書き、`tailwind.config.ts` の `theme.extend.colors` から参照する。

```css
/* apps/web/src/styles.css */
:root {
  /* surface */
  --color-bg-base:     #FFFFFF;     /* メイン背景 */
  --color-bg-muted:    #F7F7F5;     /* 軽いオフホワイト (カード / app bar) */
  --color-bg-elevated: #FFFFFF;     /* sheet / modal */
  --color-bg-overlay:  rgba(0, 0, 0, 0.45);  /* sheet backdrop */

  /* text */
  --color-text-primary:   #1C1B1F;  /* ほぼ黒 (Material 3 on-surface) */
  --color-text-secondary: #5F5E64;
  --color-text-tertiary:  #9CA3AF;
  --color-text-on-accent: #FFFFFF;
  --color-text-on-danger: #FFFFFF;

  /* border */
  --color-border-subtle:   #E7E5E0;
  --color-border-default:  #D1D5DB;
  --color-border-emphasis: #9CA3AF;

  /* accent (mint = Tailwind emerald-500) */
  --color-accent-50:  #ECFDF5;
  --color-accent-100: #D1FAE5;
  --color-accent-500: #10B981;
  --color-accent-600: #059669;
  --color-accent-700: #047857;

  /* status colors (6 出欠状態 + 未記録) */

  --color-status-none:      #D1D5DB;   /* light gray (未記録) */

  /* course palette (8 色、Tailwind の bg-{c}-100 + border-{c}-500 を利用) */
  /* 文字列ではなく Tailwind class 直指定で運用。COURSE_PALETTE 配列を shared に置く */

**accent 色の最終決定**: `#10B981` (Tailwind emerald-500) を採用。理由:
- Penmark 系のミントグリーン路線で学生市場に既視感
- Tailwind デフォルトと完全一致するので、`bg-emerald-500` / `text-emerald-500` 等が `tailwind.config.ts` 拡張なしで全部使える (`bg-emerald-100` / `border-emerald-500` の course palette もそのまま運用可)
- Penmark の `#00C2A0` も検討したが、Tailwind 互換性を取って `#10B981` 確定。Touri 確認不要 (Researcher §10 #1 を Architect 判断で確定)

## 3. ナビゲーション構造

### 3.1 5 タブ

| #   | アイコン (lucide-react)       | ラベル        | route          | 役割                                             |
| --- | ----------------------------- | ------------- | -------------- | ------------------------------------------------ |
| 1   | `Home` (or `CalendarCheck`)   | 今日          | `/`            | 当日 occurrence + ワンタッチ出欠 + サマリ        |
| 2   | `LayoutGrid`                  | 時間割        | `/timetable`   | 週間グリッド + bottom sheet CRUD                 |
| 3   | `Search`                      | みんなの時間割 | `/templates`   | 学校・学科で検索 → コピー                        |
| 4   | `BarChart3`                   | 出席率        | `/stats`       | Course ごとの出席率                              |
| 5   | `UserCircle`                  | マイページ    | `/me`          | プロフィール + 設定 + 学期管理 + ルール          |

- **アイコンは `lucide-react`** を採用 (SVG sprite、SwiftUI 移行時に SF Symbols へ 1:1 マップ可能なものを選ぶ)
- 5 個固定 (3-5 個範囲、MD3 / iOS HIG 推奨)
- 旧 `/settings` → `/me` に renaming、`Setup.tsx` 配下に redirect は不要 (主要ナビからは消えるだけ)

### 3.2 モバイル時のレイアウト (`< 768px`)

```
┌──────────────────────────────┐
│  TopBar (h-12, bg-bg-muted)  │  ← ページタイトル + 右上アクション 1 個まで
├──────────────────────────────┤
│                              │
│  <Outlet />                  │  ← min-h-[100dvh - top - bottom]
│  (scrollable)                │
│                              │
├──────────────────────────────┤
│  BottomTab (h-14, sticky)    │  ← safe-area-inset-bottom 加算
└──────────────────────────────┘
```

- **TopBar** は最小限。中央にページタイトル (`<h1 className="text-base font-semibold">時間割</h1>`)、右上 1 個まで icon button (歯車 / フィルタ等)。左上は戻る矢印が必要なフロー (Setup wizard / 404) でのみ表示
- **BottomTab** sticky bottom、`padding-bottom: env(safe-area-inset-bottom)`、`bg-bg-muted`、上端 1px border-subtle
- アクティブ: アイコン fill (もしくは emerald 色) + ラベル emerald + 太字 + 上端 2px emerald indicator bar
- 非アクティブ: アイコン line + ラベル `text-fg-secondary`
- タップターゲット: タブ 1 個 `flex-1 min-h-14`、WCAG 2.2 `target-size-minimum` クリア
- 仮想キーボード対策: `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">` を `index.html` で指定 (Chrome の自動調整に任せる、iOS Safari は input focus 時に `display:none` で逃げる) — §10 罠参照

### 3.3 デスクトップ時のレイアウト (`>= 768px`)

```
┌──────┬───────────────────────┐
│      │  TopBar (h-12)        │

- 右側コンテンツは `max-w-[960px] mx-auto`、横余白 `px-6`

- `/signin` `/verify` `/setup` は **bottom tab・sidebar を非表示**にする `<AuthLayout>` を使う (`<Outlet />` のみ centered, max-w-md)

### 4.1 Today (`/`, `Today.tsx`)

#### 構成要素

1. **挨拶エリア**: マスコット (56px) + 日付 (`M月D日(曜)` 大、`YYYY-MM-DD` 小) + 「こんにちは ${user.name ?? 'こんにちは'}さん」
2. **今日のミニ時間割**: 連続バー (`<TodayMiniTimeline>` component)。横軸 = 1 日の時間 (`startMinute(min)` to `endMinute(max)` を縮尺)、各 occurrence を accent 色のセグメントで配置。tap で `/timetable` (今日の曜日列に scroll)
3. **未記録カウンタ**: `未記録 N 件 / 全 M 件`、N=0 のとき緑文字「本日の記録は完了済」、M=0 のとき隠す
4. **当日 occurrence カード**: `OccurrenceCard` を縦並び (`flex flex-col gap-3`)、`startMinute` 昇順。連続コマは 1 カードに merge ("2-3限" 表示)
5. **当日授業ゼロ時**: `<EmptyState />` で中央にマスコット 180px + 「今日は授業がありません」+ 「時間割を見る」ボタン
6. **sticky CTA**: 画面下に `<StickyAction>`、未記録 N > 0 のとき `全部出席にする (N 件)`、N=0 のとき disabled で `本日の記録は完了済`。bottom tab の上に 8px gap で重ねる (z-index 制御)

#### 挙動

- マウント時: `useToday()` (TanStack Query) で `GET /api/today` を fetch
- カードの StatusChip tap → `<AttendanceSheet occurrenceId={id} currentStatus={status}>` bottom sheet open
  - sheet 内に 6 状態 (`出席 / 欠席 / 公欠 / 遅刻 / 早退 / 休講`) + 「記録を消す」+ note 入力欄
  - 状態 tap → 即 `POST /api/attendance/:id` → sheet 自動 close
  - 「記録を消す」 → `DELETE /api/attendance/:id`
- 「全部出席にする」 → `POST /api/attendance/mark-all-present` → optimistic に未記録カードを `PRESENT` 更新 → success で確定、failure で rollback + toast
- 連続コマの occurrence (`periodOffset=0,1,...`) は **同じ Course なら 1 カードに合体表示** だが、出欠は **occurrence 単位で独立**。カード内に「1 限: 出席 / 2 限: 未記録」のように分割 chip を出す (片側だけ操作するときは sheet で対象選択)

#### グリッド構成 (`<TimetableGrid>` component)

- CSS Grid: `grid-template-columns: 48px repeat(N_DAYS, minmax(0, 1fr))`、`grid-template-rows: 32px repeat(N_PERIODS, minmax(64px, 1fr))`
- N_DAYS は時間割の `daysOfWeek` (デフォ 月-金 = 5、`UserTimetable.daysOfWeek` を将来追加可能だが MVP は 5 固定で `[1,2,3,4,5]`)
- N_PERIODS は `userTimetable.daySlots.length` (1-12)
- 1 行目 = 曜日ヘッダ、1 列目 = 時限ラベル (`1` `2` ...)
- セルは `<TimetableCell>` (空きセル) または `<MeetingBlock>` (Meeting 配置済)
- **連続コマ**: `<MeetingBlock>` に `style={{ gridRow: \`${row} / span ${periodCount}\` }}` を渡し、内部分割線を出さない
- **左 4px accent border**: `border-l-4` (course color に紐づく Tailwind 色) を全 MeetingBlock に付ける
- **カード背景**: `bg-{color}-100` (淡色)、`text-fg-primary`
- 時刻表示: `${startMinuteLabel} - ${endMinuteLabel}` (連続コマ全体の start - end)

#### 挙動

1. **空きセル tap** → `<MeetingCreateSheet day={d} periodIndex={p}>` 開く
   - フォーム: 科目 (既存 Course 選択 dropdown + 「新規作成」ボタン) / 連続コマ数 (1-8) / 教師 / 教室 / 色 (palette 8 色)
   - 「新規作成」を選ぶと sheet 内で `<CourseEditor>` フォームが展開 (name / teacher / room / color / totalSessions)
   - 「保存」 → `POST /api/courses` (新規時) → `POST /api/meetings { dayOfWeek, startPeriodIndex, periodCount, courseId }`
2. **既存セル tap** → `<MeetingDetailSheet meetingId={id}>` 開く
   - 表示: 科目名 / 時刻範囲 / 教師 / 教室 / 色
   - フッタ: `[編集]` (左, secondary) / `[削除]` (右, destructive)
   - `[編集]` → 同 sheet が `<MeetingEditForm>` に切替 → 保存で `PATCH /api/meetings/:id`
   - `[削除]` → 確認 dialog (「このコマを削除しますか? 関連の出欠記録も削除されます」) → `DELETE /api/meetings/:id` (cascade で MeetingOccurrence + AttendanceRecord も消える)
3. **TopBar 右上歯車 tap** → `<TimetableSettingsSheet>` 開く
   - 時限数 [- N +] (1-12)、各時限の `label` (text input) + `startMinute` + `endMinute` (`<input type="time">`)
   - 「標準時刻に戻す」 (デフォ preset を投入する secondary ボタン)
   - 「保存」 → `POST /api/user-timetables/:id/day-slots/bulk-replace`
4. **学期切替 select** → `useNavigate` で `?semesterId=` を query に乗せる、`useUserTimetable(semesterId)` で fetch
5. **時間割ゼロ件** (該当 semester に UserTimetable 無し) → empty state「この学期の時間割がありません。テンプレから選ぶ / 自分で作る」(両ボタン)

#### 連続コマ衝突検知

- 「2 限固定の授業を 3 連続コマに変更」しようとして、3-4 限に他の Meeting がある → サーバ側で `409 PERIOD_CONFLICT` を返す
- フロントは toast + sheet 内 inline エラー「3-4 限に他の授業があります」

### 6.3 DaySlot 操作 (新規追加)

新規ルート `apps/api/src/routes/daySlots.ts`。

| Method | Path                                          | 認証          | Request                          | Response                          | エラー                              |

```ts
// packages/shared/src/schemas/daySlot.ts (新規。既存 DaySlotDto は維持)
export const DaySlotUpdateInput = z.object({
  label: z.string().max(20).optional(),
  startMinute: z.number().int().min(0).max(1440).optional(),
  endMinute: z.number().int().min(0).max(1440).optional(),
  isBreak: z.boolean().optional(),
}).refine(v => v.startMinute == null || v.endMinute == null || v.startMinute < v.endMinute, {
  message: "startMinute must be < endMinute",
});

export const DaySlotBulkReplaceInput = z.object({
  daySlots: z.array(DaySlotDto).min(1).max(12),  // periodIndex 1..N の連番、N = daySlots.length
}).refine(v => {
  // periodIndex は 1..N の連番
  const idxs = v.daySlots.map(s => s.periodIndex).sort((a, b) => a - b);
  return idxs.every((idx, i) => idx === i + 1);
}, { message: "periodIndex must be 1..N continuous" });
```

**挙動**:
- `PATCH /api/day-slots/:id`: 個別の DaySlot を更新 (label / 時刻 / isBreak)。既存 MeetingOccurrence の startMinute/endMinute snapshot は **更新しない** (snapshot を維持、Architect 判断: 過去の出欠記録の時刻表示を変えない)
- `POST /api/user-timetables/:id/day-slots/bulk-replace`: 時限数変更時の一括置換
  - 既存 DaySlot を全削除 → 新 DaySlot を投入
  - 既存 DaySlot を参照する Meeting (`startPeriodIndex + periodCount - 1 > N`) がある場合 `409 { code: "CONFLICT", details: { reason: "PERIOD_OUT_OF_RANGE", offendingMeetings: [...] } }`
  - 削除予定の periodIndex に Meeting が「範囲内に収まる」場合 (例: 5 限 → 8 限への拡張) は OK、Meeting は無事
  - 縮小時 (8 限 → 5 限) で 6-8 限に Meeting がある場合は 409、フロントは「6-8 限の授業を削除してから時限数を変更してください」inline error
- 拡張時の挙動 (5 限 → 8 限): 6,7,8 限の DaySlot は **デフォルト時刻を計算** (5 限の終了から休憩 10 分後 + 90 分単位)、または `bulk-replace` の入力 daySlots に user 指定の時刻を含める形

## 7. キャッシュ無効化 (TanStack Query)

「リロードしないと反映されない」問題 (Researcher §0 ★3 含意) を根治するため、**全 mutation の invalidate 対象を表で明示**。Developer はこの表に従って `queryClient.invalidateQueries({ queryKey })` を発行する。

### 7.1 Query key naming convention

### 7.3 共通 hook 雛形 (`apps/web/src/api/hooks/useApiMutation.ts`)

```ts
export function useApiMutation<TVars, TData>(
  mutationFn: (vars: TVars) => Promise<TData>,
  invalidate: Array<readonly unknown[] | { predicate: (q: Query) => boolean }>
) {
  const qc = useQueryClient();
  return useMutation({
    mutationFn,
    onSuccess: () => {
      for (const target of invalidate) {
        if (Array.isArray(target)) qc.invalidateQueries({ queryKey: target });
        else qc.invalidateQueries({ predicate: target.predicate });
      }
    },
  });
}
```

各 mutation hook (`useCreateMeeting`, `useDeleteMeeting` 等) は上記 `useApiMutation` を使い、§7.2 の表に従い `invalidate` を渡す。

### 7.4 Optimistic update

| 操作                              | optimistic 戦略                                                                                            |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 出欠状態切替 (`POST /attendance`) | `["today"]` キャッシュの該当 occurrence.status を即更新、失敗で rollback + toast                          |
| 「全部出席」                       | 未記録 occurrence を `PRESENT` に即更新、失敗で全 rollback                                                 |
| Meeting 作成・編集・削除           | optimistic にしない (PERIOD_CONFLICT 検証がサーバ側で確定する必要があるため)。loading spinner で待たせる    |
| Course / DaySlot 編集              | optimistic にしない (検証が複雑)                                                                            |

## 10. 既知の罠 (実装で予防)

MVP doc §14 の罠 (Hono error status / jsdom getBoundingClientRect / Coolify HTTPS / Prisma Dockerfile / Magic Link URL 構築) は **全て継続有効**。本節は redesign UX 由来の罠を追加。

| #   | 罠                                                              | 予防策                                                                                                              |
| --- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| R1  | safe-area-inset-bottom 漏れで iOS bottom tab がホームインジケータに被る | `index.html` に `<meta name="viewport" ... viewport-fit=cover>` 必須、BottomTab に `padding-bottom: env(safe-area-inset-bottom)` |
| R2  | TanStack Query invalidate 漏れでリロードまで反映されない         | §7.2 マトリクス必須遵守、Developer が hook 作成時に表を引く                                                          |
| R3  | CSS Grid `grid-row: span N` が時限数変更で計算ずれ              | row index は `headerOffset (1 行ヘッダ分) + startPeriodIndex` で計算、span は periodCount 直当て                    |
| R4  | iOS Safari `100vh` で bottom tab が下に隠れる                    | `min-h-dvh` / `100dvh` を必ず使用、`vh` は使わない                                                                  |
| R5  | bottom sheet 開いた状態でリロード → 状態消える                   | MVP では受容 (close で消える)、復元は v1.5。「保存」前にユーザーが離脱しても data loss を許容                       |
| R6  | iOS Safari の `<input type="time">` で 24h 形式が出ない         | `<input type="time" step="60">` + `defaultValue="HH:mm"` 形式で渡す、parsing は dayjs                              |
| R7  | tailwind 4 の `@theme` 構文と CSS custom properties 混在で var() 解決失敗 | `@theme` 内で直接色値を書かず、`var(--color-*)` を CSS class で参照する形に統一 (§2.4)                              |
| R8  | TanStack Query の useInfiniteQuery で cursor 不一致              | cursor は `${updatedAt}|${id}` の base64、server 側で同じ形でパース、両端で同じユーティリティ関数使う                |
| R9  | lucide-react の SVG が tree-shake されない                       | `import { Home } from "lucide-react"` 個別 import を徹底 (`import * as ...` 禁止)                                  |
| R10 | bottom sheet の drag handler が input focus と競合 (iOS)         | sheet 内 `<input>` focus 時は `pointerdown` を sheet root で `e.preventDefault()` しない (input にイベントを通す)   |
| R11 | dayjs timezone plugin の locale 読み込み忘れ                     | `apps/web/src/lib/dayjs.ts` で `dayjs.extend(utc); dayjs.extend(timezone); dayjs.tz.setDefault('Asia/Tokyo')` 必須   |
| R12 | 連続コマ Meeting 削除時に MeetingOccurrence cascade 漏れ         | Prisma schema の `onDelete: Cascade` を全 FK で明示 (MVP schema 既に確認済)                                          |

## 13. Touri 承認段で確認したい論点

設計を Architect 単独で決め切ったため、Touri 承認は **形式確認のみ**。論点は以下 2 つ:

1. **マスコット 1 種固定 (Phase 1.5 で表情違い)** — Researcher の case が許容 + Touri が「新 design 言語と整合するか Architect 判断」と委任しているため `hello` 1 種で確定。Touri が「`thinking` も MVP に欲しい」なら追記
2. **Course 削除時の cascade ダイアログ仕様** — `USED_BY_MEETING` 時に「関連の授業 N 件も削除」を許容したが、Touri が「削除させずに先に Meeting を消させる」UX を望むなら 409 + inline error のみ (cascade=true 不要)

それ以外は本 doc の判断で進めて問題ない。
